# 数据定义

刷卡事件以event_id去重，card保留前导零。route支持1路/01等别名。event_time必须带偏移；业务日为Asia/Shanghai。result仅success可作为行程，失败刷卡隔离。reported为实扣人民币元。票价F1至2026-11-01前为2元，F2为2.50元。

跨线路换乘必须在上一次实际付费行程后60分钟内，恰好60分钟排除。同线路无优惠；零付费行程不能延长换乘锚点。先扣1元换乘优惠，再对卡号业务日施加6元封顶。每条基本票价=实算扣费+换乘优惠+封顶优惠。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。
## 更正账

晚到撤销或补录不覆盖已清分行。更正登记为独立账册版本，受影响卡日按 `(card, business_day)` 整日重算：撤销行移出，补录行走与导入相同的线路、票价、行程规则，再按同卡同刻、锚点、换乘窗与封顶顺序重排。未受影响卡日逐行结转。换乘锚点与日封顶只在同一卡日内联动，因此按卡日重算与原清分规则一致，不会跨卡日扩散。

每笔更正保留 `original_basis`（原清分中受影响的卡日行）、`replaced_rows` 与 `final_rows`，并生成调整分录：`VOIDED`、`ADDED` 或 `ADJUST`。调整分录的 `delta.expected`/`delta.cap_discount`/`delta.transfer_discount` 之和必须等于终版与上一版账册指标之差，`delta.day_paid` 仅在前后两版都存在该行程时给出。日终结果统一取末版账册的应收、换乘命中、封顶减免与逐行差异，不允许页面与导出各引一版。

幂等键为撤销事件集合加补录内容（按列归一、排序），不含措辞；相同业务效果的重试返回原未退回的更正单与 `replayed=true`。更正本身须复核且裁决后封闭：只有末笔更正为 `已复核` 才计入日终账册，`待复核` 与 `退回复核` 均不改账；末笔未复核或退回时 `settlement.ready=false`，日结归档与证据导出返回409，需重新登记并复核同一依据。
